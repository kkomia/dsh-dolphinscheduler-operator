# 海豚算子节点环境事实（模板）

> 本文件是 `REFERENCE.md` 的公开模板。真实的 `REFERENCE.md` 是按你的调度集群实测出来的
> 环境事实，通常包含内网地址、主机名、数据库名与凭据位置等内部信息，因此**不随本仓库分发**。
>
> 使用方法：把你的报告放到
> `assets/skills/dolphinscheduler-python-operator/REFERENCE.md`，然后重新激活插件
> （重启 DSH Desktop，或 `remove_bundle` 后再 `install_bundle`）。模型的 skill 资源目录里
> 就能读到它。`SKILL.md` 本身不依赖本文件，缺少它时 skill 仍可正常加载，只是少了环境细节参考。

## 建议覆盖的 15 个方面

1. **执行身份与权限**：租户、实际执行用户、提权方式、初始工作目录、可读的敏感面。
2. **操作系统与硬件**：发行版、内核、架构、CPU / 内存 / Swap、可用的系统工具。
3. **容器与部署形态**：是否容器化、DolphinScheduler 部署模式、Master / Worker 是否同一 JVM。
4. **文件系统与存储语义**：各挂载点的可写性 / 持久性 / 配额、对象存储与 HDFS 端点、
   路径前缀映射、跨算子是否留存。
5. **Python 运行时**：解释器路径、版本、虚拟环境、site-packages、pip 源。
6. **Java 与大数据组件**：JDK 版本、Spark / Hadoop / Hive / Kyuubi 等组件可用性与关键路径。
7. **网络与互通**：可达性矩阵（按你的环境脱敏）、代理、DNS 行为。
8. **调度与算子执行机制**：脚本落盘位置、进程谱系、平台超时行为、日志行数 / 行长上限。
9. **参数传递机制**：IN / OUT 参数、`${...}` 文本替换、`setValue` 语法、`system.*` 行为。
10. **依赖管理与包源**：pip 源、预编译轮子情况、缺包时的安装策略。
11. **资源与限额**：cgroup 限额、磁盘配额、内存 / CPU 的可见性。
12. **安全与凭据面**：哪些路径包含明文凭据（**只记录位置与处理方式，不要抄写凭据值**）。
13. **数据平台技术栈**：各组件版本与端口。
14. **已知问题与风险清单**：实测缺陷、配置不一致、规避方式。
15. **未决事项**：待补测清单。

## 写作约定

- 每条结论标注证据等级：`[实测]` / `[推断]` / `[未决]`，并附上取证方式。
- 结构化配置用解析器读取，不要用 `grep` 拼凑（容易静默错位）。
- 公开或共享前先脱敏：内网 IP、主机名、凭据、库名、内部项目名。
- 建议附一节**可粘贴的验证探针**（例如参数嵌套取值），把「未决」项闭合为「实测」：
  探针要能整段粘进算子正文，并写清判读规则与「跑完怎么回写证据等级」。
